# Ask User：按需等待用户决策

加载仓库 package，或临时加载单个扩展：

```bash
pi --extension ./extensions/ask-user.ts
```

已加载的运行时需要重新加载扩展后才能看到新增工具和提示词。本扩展不直接创建网络连接、不执行外部命令；与已启用的 voice 联动时会委托 voice 向配置的网关发送语音文案并播音。问题、选项与答案会进入当前 Pi 会话历史，并可能作为上下文发给模型，不要通过问卷收集密钥等敏感信息。自动通知在 Agent 空闲时可能启动新一轮模型调用。

## 工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `ask_user_question` | `questions`，可选 `blocking`（默认 `true`）、`voice_prompt` | 默认等到用户提交或取消后返回；`false` 时立即返回请求状态和 `requestId`，用户回答期间 Agent 可继续工作 |
| `get_user_answer` | `requestId` | 立即查询，不等待 |
| `wait_user_answer` | `requestId` | 未完成时等待；已回答、取消或失败时立即返回 |

每个问卷支持 1–4 题，每题提供 1–12 个选项；每项有 `label` 和 `description`，每题可设置 `header`、`multiSelect`。自定义输入选项由界面追加，不需要 LLM 手写 Other。

返回文本包含 `requestId` 与状态；工具结果的 `details` 保存结构化快照，包括题目、答案和取消状态。正常状态为 `pending`、`answered`、`cancelled` 或 `error`。当前分支找不到 ID 时返回 `not_found` 错误，不会一直等待。

### 推荐流程

1. 有待确认的决策，但还能做独立工作：`ask_user_question({ blocking: false, questions: [...] })`。
2. 保存返回的 `requestId`，继续读代码、运行现有测试等不依赖选择的工作。
3. 如果只是想知道有无答案，调用 `get_user_answer({ requestId })`；不要循环轮询。
4. 当下一步确实需要用户决定时，调用 `wait_user_answer({ requestId })`。
5. 根据实际答案行动。未回答、取消、失败和查不到请求都不是同意，也不能擅自采用推荐项。

非阻塞问卷完成、取消或失败后自动发送包含请求 ID 的 `steer`（steering）消息。Agent 忙时在下一个可处理边界插入，不等待当前任务全部结束；这可能跳过尚未执行的工具，但不会强制中止已经运行的工具。Agent 空闲时自动启动一轮。也可主动查询或等待答案，无需等通知被处理。等待工具返回答案后，也可能随后看到同一请求的通知；这是同一条决策，不是新的授权。

**“非阻塞”指不阻塞 Agent 的工具执行，不是同时打开多个交互框。** 问卷仍使用原有底部交互区，支持 `Ctrl+]` / `Alt+H` 最小化。多个请求按 FIFO 展示，包括默认阻塞请求；排队中的问卷也处于 `pending`。依赖后一个问卷的等待，需要用户先完成或取消前面的问卷。

### 示例：先提问，继续检查，到实现时再等答案

```json
{
  "blocking": false,
  "questions": [{
    "header": "配置兼容",
    "question": "新配置格式如何兼容现有配置？",
    "options": [
      {
        "label": "兼容旧格式 (Recommended)",
        "description": "同时读取新旧格式，现有用户无需立即迁移；由于这次要求平滑升级，推荐此项。代价是保留两套解析逻辑，并增加兼容性测试和后续维护成本。"
      },
      {
        "label": "只支持新格式",
        "description": "只维护新解析器，代码与测试更简单；现有配置必须先迁移，否则升级后无法读取。适合允许破坏性升级且能统一完成迁移的场景。"
      }
    ]
  }]
}
```

工具立即返回请求 ID 后，LLM 可先读当前配置解析代码、跑现有测试；真正修改兼容逻辑前调用：

```text
wait_user_answer({ "requestId": "<提问返回的 ID>" })
```

## 与 Voice 联动：语音呼叫或直接提问

同时加载 `ask-user` 和 `voice`，执行 `/voice on` 后，问卷展示时会自动发声，无需 LLM 先调用 `voice_speak`。单独加载 ask-user、voice 关闭或无 UI 时不会播音。

- 可选 `voice_prompt`（1–500 字符）：**具体说什么由当时的 LLM 判断**，可以呼叫用户、直接朗读问题，或简短概括待确认的选择。提示词要求口语化的 1–2 句，不朗读代码、路径或长选项；不要为同一问卷再调用 `voice_speak`。
- 省略或仅空白时使用固定呼叫：“有个问题需要你确认，请看一下终端。”不会自动朗读完整题目和选项，减少意外泄露。
- 每份问卷仅在轮到它展示时提醒一次，多题共用一段文案；排队、查询、等待、恢复历史都不重复播音。默认阻塞与 `blocking: false` 均支持，TUI/RPC 均可使用已启用的网关。
- 播音不阻塞窗口或答案交付。提交、取消、会话重载或分支切换会取消仍在运行的提醒；非阻塞问卷的提醒不随原工具调用结束或中止而取消。仅取消 `wait_user_answer` 不影响提醒。
- 复用 voice 默认音色、语速与音频互斥；显式音频工具占用通道时跳过提醒，网关失败也不自动重试，问卷仍可正常回答。已开启的 Live 按既有 speak 语义暂停/恢复；本功能**不自动开启录音，不把语音识别当成答案**。
- 这是进程内事件桥接，不启动额外服务。语音文案与其他工具参数一样可能保存在会话中；发声内容会发送到网关并被周围人听到，请避免敏感信息。继承 [VOICE-001](known-issues.md) 的全局抢占/停播及物理播放完成限制，多终端共用网关时尤其注意。

```json
{
  "voice_prompt": "需要你确认一下，旧配置要继续兼容，还是直接切到新格式？",
  "questions": [{
    "question": "是否继续兼容旧配置格式？",
    "options": [{
      "label": "继续兼容",
      "description": "同时读取新旧格式，现有配置无需立即迁移；代价是维护两套解析逻辑。适合需要平滑升级的场景。"
    }]
  }]
}
```

## 选项说明的提示词约束

工具描述和 `options[].description` 的 schema 说明同时要求：

- **具体做法与影响**：选了以后会改变什么，影响哪些行为、用户或范围。
- **收益与代价**：说明主要优点，也交代风险、限制，以及相关的成本和兼容性问题。
- **推荐理由**：结合本次用户目标和约束，解释为何更合适；不能用“推荐”“更好”“更灵活”代替理由。
- **其他选项的适用场景**：用户应能直接比较，而不是看不懂的技术标签。
- **不确定性**：未知影响如实标明，不编造性能提升、成本数字或确定性。

`description` 在 schema 中仍为可选，以兼容旧调用；新提示词要求每项填写。这是生成指导，不是对文案质量的自动语义校验。

## 取消、持久化与模式边界

- 默认阻塞提问保持原行为：中止该工具会取消问卷；用户按 `Esc` 也能取消。
- 非阻塞问卷在原工具返回后继续存活；原调用信号之后被中止，不会销毁问卷。用户仍可用 `Esc` 取消。
- 中止 `wait_user_answer` 只停止等待，不取消或消耗答案；之后仍可查询或再次等待。
- 每个请求最终状态只通知一次；默认阻塞提问不发送额外通知。
- 非阻塞答案先保存会话条目，再排入自动通知。通知失败时仍可查询内存中的答案。
- 会话关闭、重载或树分支切换会关闭当前问卷、清空待展示队列、释放等待，并阻止旧回调向新会话发送答案。
- 恢复状态仅遍历当前分支：已完成答案可查询；历史中尚未完成的请求标记 `cancelled` 并说明被中断，需要时重新提问。不重开旧弹窗、不重复通知、不复用其他分支的答案。
- TUI 保持原有 Review、多选、自定义回答和宽度安全。RPC 使用客户端支持的 `select` / `input` 顺序交互，也支持非阻塞返回；实际界面呈现取决于客户端。
- 无 UI 环境返回原有不可交互提示，不创建永远等不到答案的后台请求。非 TUI 模式不输出终端控制字节。

## 验证

自动回归：

```bash
node scripts/test-ask-user.mjs
node scripts/test-ask-user-voice.mjs
npm run check
npm run validate
```

可重复的 TUI 手工验证（需实际运行 Pi）：

1. 让 Agent 使用 `blocking: false` 提问，同时继续读取文件；不回答，确认工具已返回且后续工作继续。
2. 让 Agent 调用 `get_user_answer`，确认立即返回 `pending`；再调用 `wait_user_answer`，确认此时才等待。
3. 提交答案，确认等待工具返回所选项，自动消息含同一请求 ID。另在 Agent 持续工作时提交或取消问卷，确认 steering 在下一个可处理边界送达，无需等整个任务结束；尚未执行的工具可能被跳过，已经运行的工具不会被强制中止。
4. 连续创建两个问卷，确认只显示第一个；提交或取消后才展示第二个。
5. 在显式等待时中止等待，随后继续回答，确认能查询到答案。默认阻塞提问中止时则应关闭问卷。
6. 完成一题、保留另一题未回答，重新加载或切换分支；确认完成项仅在包含它的分支可恢复，未完成项标记取消，不出现旧问卷或串入旧答案。
7. 同时加载 voice 并执行 `/voice on`，让 LLM 用 `voice_prompt` 提问，确认只播一遍且窗口立即出现；省略文案时听到固定呼叫。排队的第二份问卷在展示时才播音。回答/取消时应取消未结束的提醒；`/voice off` 后再次提问不出声。此步骤会真实播音，仅在了解 VOICE-001 且无其他客户端争用的环境手动执行。
8. 检查推荐项是否解释“为什么适合当前需求”及代价，其他项是否写清影响和适用场景；调整终端宽度并进入 Review，确认长描述仍可读。
